Before you pick a tool, decide which of two jobs you have. Excel to website or web app is the first fork in the road, and most search results blur the two. A website shows your spreadsheet to readers. A web app lets people change it, log in and work with their own records. They need different tools, different effort and different budgets, and choosing the wrong one costs weeks.

## The difference in one table

| | Website or report | Web app |
| --- | --- | --- |
| Who changes the data | You, in Excel | Many people, in the browser |
| Visitors log in | No, or one shared password | Yes, each with an account |
| What visitors see | The same page | Their own data and permissions |
| Typical setup time | Minutes | Days to weeks |
| Examples | Price list, status report, schedule, directory | Booking system, approvals, inventory entry, customer portal |

If your visitors only read, you almost certainly need a website. If they have to enter or change anything, you need an app.

## When a website is enough

A published page is the right answer more often than people expect. Think of these cases:

- A status report for a client that you update every Friday.
- A price list or menu that changes a few times a month.
- A staff directory, class schedule or event lineup.
- A set of key numbers for your team, with a chart or two.

In each case, one person owns the data and everyone else reads it. You keep working in Excel, which you already know, and uploading a new version updates the same link. A tool like [SheetPress](/docs) is built for exactly this, and it can lay a workbook out as a real page with headings, images, buttons, charts and tables.

## When you need a web app

Look for these signals. If one of them is true, a read-only page will not be enough:

- Several people need to add or edit rows.
- Each person must see only their own records.
- You need approvals, status changes or notifications triggered by data.
- You take payments or collect forms.

For these jobs, no-code app builders import your spreadsheet as data and build screens around it. [Glide](https://www.glideapps.com/blog/excel-based-web-application) advises arranging your spreadsheet like a simple database table first, [Knack](https://www.knack.com/blog/converting-excel-to-web-app/) turns rows into database records, and [Caspio](https://go.caspio.com/convert-excel-to-web-app) suits larger database applications and portals. If your Excel file is really a calculator, [SpreadsheetWeb](https://spreadsheetweb.com/excel-to-web-app/) focuses on keeping formulas working in the browser.

Expect to spend time on the parts a spreadsheet never needed: user accounts, permissions, screens for each role, and testing what each kind of user can do.

## A middle path: start read-only

You do not have to decide forever. A common pattern is to start with a read-only page, learn what people actually ask for, and move to an app only if the need is real. Many teams discover that a shared page and a password cover 90 percent of what they imagined needing an app for.

SheetPress sits at the read-only end, with one exception: it includes editable checklists and shopping lists you manage in the browser. It does not have forms or visitor accounts. If you outgrow it, your data is still your Excel file, so moving to an app builder later is a matter of importing the same workbook.

## Questions to ask before you choose

1. Who changes the data, and how often?
2. Do readers need to log in, or is one shared password enough?
3. Does anyone need to see data that others must not see?
4. Do formulas have to recalculate for the visitor?
5. How much time can you spend setting this up?

If the honest answers are "only me", "no", "no", "no" and "not much", publish a page. Our step-by-step guide to [turning an Excel file into a website](/blog/turn-excel-into-a-website) takes about ten minutes.

## Frequently asked questions

### Is a website cheaper than a web app?

Usually, yes, in both money and time. A read-only page has no accounts or permissions to design, so there is less to build and less to maintain.

### Can I add a password to a website made from Excel?

Yes. A password on the page keeps the data from anyone who does not have it. See [how to share an Excel report online with a password](/blog/share-excel-report-online-with-password).

### How do I compare tools if I already use Google Sheets?

The same decision applies. If readers only need to see the data, you want a publishing tool. If they must edit it, you want an app builder. Our list of [Sheet2Site alternatives for Excel users](/blog/sheet2site-alternatives-for-excel) compares both types.
